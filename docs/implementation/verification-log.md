## What the statuses rest on

- `VERIFIED` rows cite a named committed test or a directly exercised code path. The
  checker confirms that every cited function name exists in `HEAD` under `src/` or
  `tests/`. It does not run those tests in this session.
- `IMPLEMENTED` rows cite code at HEAD and, where relevant, note that runtime evidence in
  `.opencode/MEMORY.md` was not re-run.
- `ANALYZED` rows cite a design decision in `architecture-decisions.md`.
- `DISCOVERED` and `BLOCKED` rows cite draw.io documentation and a concrete missing
  subsystem or scope decision.

## What was not run

- `cargo test` was not run. The suite rewrites the committed screenshots in
  `docs/screenshots/`, and this task is restricted to `docs/implementation/` and
  `.artifacts/`. The working tree also contains unrelated in-flight changes.
- `cargo clippy --all-targets -- -D warnings` and `cargo fmt --check` were not run for the
  same reason: they are application checks, and this task changed only Markdown and
  `.artifacts/` scripts.
- No runtime check of the desktop app was performed. The round 5 runtime notes in
  `.opencode/MEMORY.md` are recorded context, not evidence gathered in this session.
- No `.drawio` file was imported or exported. The adapter is absent by design and is
  planned for M5.
- No browser check was performed. There is no `site/` change in this task.
- No network re-fetch of the draw.io pages was performed. Only the saved corpus was
  checked.
- No multi-platform check was performed. The baseline and the tests are read from this
  Linux checkout.

These limits apply to the planning pass. The M1 working tree section was run later and
does not change the baseline status decisions in the inventory.

## Unverified claims that remain

These are known gaps in this documentation pass, not necessarily product bugs:

1. A `VERIFIED` row means the committed test or code path exists and supports the claim.
   The test was not executed here, so a stale or flaky test would not be caught.
2. The round 3 to round 5 inspector runtime evidence in `.opencode/MEMORY.md` was not
   replayed. Rows that depend on it are marked `IMPLEMENTED` unless a committed test
   covers them.
3. The draw.io documentation corpus was not re-crawled. A page could have changed after
   the crawl. The behavior statements are only as current as the saved text.
4. The inventory does not attempt a competitive feature comparison with Figma, Paper, or
   Excalidraw. It records draw.io behavior and Sketch's baseline only.
5. Counts describe the baseline commit, not the working tree. Uncommitted page settings,
   font work, and style fields are not counted.
6. The roadmap estimates are sequencing decisions, not schedule commitments. No task was
   estimated in hours or days.
